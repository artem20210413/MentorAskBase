# Quickstart: Telegram-бот + авторизація та ролі

**Feature**: `004-telegram-bot-auth-roles`

## Передумови

- Застосунок піднятий локально (Sail), БД мігрована.
- Створено Telegram-бота через `@BotFather`, отримано токен.
- Для локального webhook потрібен публічний HTTPS-URL (напр. `ngrok http 80`), оскільки Telegram не приймає `localhost`.
- Створено груповий чат модерації в Telegram, бот додан туди з правом надсилати повідомлення.

## Налаштування

```bash
composer require spatie/laravel-permission irazasyed/telegram-bot-sdk propaganistas/laravel-phone

php artisan migrate
```

У `.env` заповнити (значення з `.env.example`, секція Telegram — вже додана):
```
TELEGRAM_BOT_TOKEN=<токен від BotFather>
TELEGRAM_WEBHOOK_SECRET=<випадковий рядок>
TELEGRAM_MODERATION_CHAT_ID=<id групового чату, напр. -1001234567890>
SESSION_LIFETIME=480
```

Створити першого super admin (поза загальним флоу апрову, FR-025):
```bash
php artisan telegram:create-super-admin --phone="+380000000000"
```

Встановити webhook (на публічний URL, напр. ngrok):
```bash
php artisan telegram:webhook-set https://<ngrok-host>/telegram/webhook/{TELEGRAM_WEBHOOK_SECRET}
```

## Сценарій 1 — онбординг і апрув нового користувача

1. Відкрити бота в Telegram, надіслати `/start`.
2. Очікувано: вітання українською + кнопка "Поділитись контактом" ([US1, AC1](./spec.md)).
3. Натиснути кнопку.
4. Очікувано: підтвердження "заявку надіслано"; у груповому чаті модерації з'являється картка заявника з кнопками "Одобрити"/"Відхилити" ([US1, AC3](./spec.md)).
5. Від облікового запису з роллю `moderator`/`admin`/`super_admin` натиснути "Одобрити" в чаті модерації.
6. Очікувано: заявник отримує повідомлення про схвалення; картка в чаті редагується (кнопки прибрано, позначка хто обробив) ([US1, AC4](./spec.md)).
7. Повторно натиснути кнопку на тій самій картці (інший учасник чи той самий) → тост "заявка вже обробена", стан не змінюється ([US1, AC5](./spec.md)).

**Перевірка в БД**: `users.status = 'approved'`, `user_approval_requests.status = 'approved'`, `admin_action_logs` містить запис `approval_approved`.

## Сценарій 2 — функції бота для approved-користувача

1. У боті відкрити головне меню → очікувано пункти: мова, довідка, список документів, інфо ([US2, AC1](./spec.md)).
2. Обрати мову, запросити список документів (якщо документів > 20 — перевірити появу кнопок "Далі"/"Назад").
3. Обрати документ за номером → отримати AI-резюме; повторний запит того ж документа тією ж мовою — відповідь має бути миттєвою (з кешу, `document_summaries`).
4. Написати довільне питання без команди → очікувано відповідь від RAG-пайплайна.

## Сценарій 3 — захищений вхід на `/admin`

1. Відкрити `/admin/login` під обліковим записом з роллю `admin`/`super_admin`.
2. Ввести номер телефону → очікувано: код приходить у Telegram-боті цього користувача.
3. Ввести код на сторінці → очікувано: доступ до `/admin` (зокрема `DocumentResource`).
4. Під іншим браузером (або інкогніто) увійти під `user`/`moderator` номером → очікувано відмову без деталей ("немає доступу").
5. Поки сесія активна, зайти як super admin в `/admin` і понизити роль цього адміна до `user` → попередня сесія має негайно вийти при наступному запиті (FR-023a).

## Сценарій 4 — керування користувачами (super admin)

1. Відкрити сторінку керування користувачами (`UserResource`, видима лише `super_admin`).
2. Змінити роль будь-якому користувачу, крім себе → переконатись, що для себе дію заблоковано.
3. Деактивувати користувача → переконатись, що бот відповідає йому повідомленням про блокування.
4. Відкрити журнал дій → переконатись, що обидві дії з кроків 2-3 там відображені з автором, ціллю і часом.
