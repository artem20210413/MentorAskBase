# Контракт: Вхід на захищену веб-форму (Filament-панель)

**Feature**: `004-telegram-bot-auth-roles`

Замінює відсутню авторизацію існуючої Filament-панелі (`/admin`, `DocumentResource`) кастомною 2-кроковою сторінкою логіну в межах тієї самої панелі (`AdminPanelProvider::login()`).

## Крок 1 — ввести номер телефону

```
GET  /admin/login            → форма (поле "номер телефону")
POST /admin/login             → { phone: string }
```

- **Rate limit** (FR-019b, перевіряється першим): не більше 3 запитів на хвилину для одного нормалізованого `phone` (`RateLimiter::tooManyAttempts`); понад ліміт → загальна відмова, без деталей.
- Нормалізувати `phone` до E.164.
- Пошук `User` за нормалізованим `phone`.
- **Якщо** не знайдено, або роль не `admin`/`super_admin` → відповідь однакова для обох випадків: загальна помилка "немає доступу" (FR-018), без уточнення причини.
- **Якщо** знайдено і роль підходить → анулювати (`invalidated_at = now()`) усі попередні незавершені `OneTimeCode` цього користувача (FR-019a), згенерувати новий `OneTimeCode` (6 цифр, TTL з конфігу), надіслати ботом у `telegram_chat_id` користувача, показати крок 2.

## Крок 2 — ввести код

```
POST /admin/login/verify       → { phone: string, code: string }
```

- Знайти найновіший недійсний-не-використаний `OneTimeCode` для `user_id`, що відповідає `phone`.
- **Невірний код**: `attempts += 1`; якщо `attempts >= 3` — код анулюється (`consumed_at = now()` без успіху, або окремий прапорець), повідомлення "код більше не дійсний, запросіть новий".
- **TTL минув**: аналогічно — потрібен новий код.
- **Вірний код**: `consumed_at = now()`, `Auth::login($user)`, в сесію записується `logged_in_at = now()`, редирект на `/admin`.

## Доступ до панелі (кожен запит)

`User::canAccessPanel(Panel $panel): bool` (контракт `FilamentUser`):
```php
return $this->status === 'approved'
    && $this->hasAnyRole(['admin', 'super_admin']);
```

## Мідлвар інвалідації сесії (кожен запит до `/admin/*`, окрім самого логіну)

`EnsureAdminSessionIsValid`:
1. Якщо немає автентифікованого користувача → пропустити (стандартний Filament-редирект на логін).
2. Якщо `session('logged_in_at') < $user->sessions_invalidated_at` (з урахуванням `null` як "ще ніколи") → `Auth::logout()`, редирект на логін із повідомленням "сесію завершено, увійдіть знову".
3. Якщо `$user->status !== 'approved'` або роль понижена нижче `admin` → те саме.

Таймаут 8 годин забезпечується стандартним `SESSION_LIFETIME=480` Laravel (без додаткової логіки).

## Побічний контракт: зміна ролі/статусу користувача (з UserResource)

Будь-яка дія super admin, що змінює `role` або `status` цільового користувача, MUST встановити `target.sessions_invalidated_at = now()` в тій самій транзакції, що й сам запис зміни (FR-023a), і додати запис в `AdminActionLog` (FR-026).
