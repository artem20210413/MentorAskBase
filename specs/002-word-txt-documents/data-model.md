# Data Model: Підтримка Word та текстових документів

Ця фіча не додає нових таблиць і не потребує міграцій — вона розширює
поведінку наявних сутностей `Document` і `DocumentChunk` (з
`specs/001-rag-ai-bot-backend/data-model.md`) на нові вхідні формати файлів.

## Document (без змін схеми)

Поле `original_name` (уже існує) стає джерелом істини для визначення
формату файлу (`.pdf` / `.docx` / `.txt`) під час обробки — розширення
файлу вже гарантовано валідне на етапі завантаження (FR-003).

Статуси (`pending`, `processing`, `processed`, `failed`, `duplicate`)
використовуються без змін для всіх форматів.

`failure_reason` для нових форматів додатково відображає:
- невалідний/пошкоджений `.docx` (не вдалося розпарсити);
- `.docx`, захищений паролем;
- `.docx`/`.txt` без розпізнаваного текстового вмісту (порожньо навіть
  після OCR зображень для `.docx`);
- `.txt` у кодуванні, відмінному від UTF-8.

## DocumentChunk (без змін схеми)

- `page_number`: для фрагментів, отриманих з `.docx` або `.txt`, MUST
  залишатися `null` (стовпець уже `nullable`, зміна CHECK/NOT NULL не
  потрібна).
- `source`: перевикористовує наявні значення enum:
  - `text_layer` — текст, вилучений напряму з `.docx` (параграфи/таблиці)
    або весь вміст `.txt`;
  - `vision_ocr` — текст, розпізнаний vision-моделлю з зображення,
    вбудованого в `.docx`.
- `position`: наскрізна нумерація фрагментів у межах документа, як і
  зараз для PDF (не залежить від сторінки).

## Нові сервісні (не БД) сутності

Ці сутності — програмні класи в `app/Services/DocumentIngestion/`, а не
таблиці бази даних; перелічені тут для повноти конвеєра обробки.

- **WordTextExtractor**: вилучає текст параграфів/таблиць `.docx` у
  порядку читання документа; повертає перелік вбудованих зображень
  (шлях до тимчасового файлу) для подальшого OCR.
- **TextFileExtractor**: читає вміст `.txt`, перевіряє кодування UTF-8.
- **VisionTranscriber**: спільна логіка "зображення → текст" через
  vision-модель, винесена з `PdfVisionExtractor` для перевикористання
  екстрактором `.docx`.

## Незмінні зв'язки

`Document hasMany DocumentChunk` — без змін. Дедуплікація за
`content_hash` (SHA-256 вмісту файлу) — без змін, працює однаково для
всіх трьох форматів, оскільки хешується сирий файл, а не вилучений текст.
