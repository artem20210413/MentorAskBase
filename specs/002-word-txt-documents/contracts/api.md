# Contract Delta: Завантаження документів (Word/txt)

Ця фіча розширює наявний контракт `POST /api/documents` з
`specs/001-rag-ai-bot-backend/contracts/api.md` — сама форма запиту/відповіді
не змінюється, змінюється лише набір допустимих форматів файлу.

## POST /api/documents (delta)

| Поле | Було | Стало |
|---|---|---|
| `file` | обов'язково; MIME `application/pdf`; ≤ 50 МБ (FR-001a) | обов'язково; MIME `application/pdf` **або** `.docx` (Office Open XML) **або** `text/plain` (`.txt`, UTF-8); ≤ 50 МБ (FR-001a, FR-005) |

**Відповідь при успіху** — без змін структури, `original_name` тепер може
мати розширення `.docx`/`.txt`:

```json
{ "id": "uuid", "status": "pending", "original_name": "handbook.docx" }
```

**Відповідь при помилці валідації (422)** — без змін структури, нові
причини відхилення (FR-003, FR-004b):

```json
{
  "message": "Файл не пройшов валідацію.",
  "errors": { "file": ["Файл пошкоджений або має непідтримуваний формат: ..."] }
}
```

Можливі нові причини (значення `failure_reason` на документі після
асинхронної обробки, GET `/api/documents/{id}`):
- `.docx`, який не вдається розпарсити (пошкоджений/підміна розширення);
- `.docx`, захищений паролем;
- `.docx`/`.txt` без розпізнаваного тексту після обробки (включно з OCR
  зображень для `.docx`);
- `.txt` у кодуванні, відмінному від UTF-8.

## GET /api/documents, GET /api/documents/{id}, DELETE /api/documents/{id}

Без змін контракту — документи всіх форматів повертаються в тому самому
форматі відповіді (FR-007), без поля, що позначає тип файлу.
