# ТЗ — Telegram-бот + авторизация и роли

Дата: 01.10.2026
Статус: на согласовании

## 1. Цель

Дополнить проект Telegram-ботом, через который пользователи общаются с AI (RAG), получают список и инфо по документам. Доступ к боту — только для одобренных (approved) пользователей. Добавляется авторизация и ролевая модель, которой также закрывается веб-форма загрузки документов.

## 2. Роли

| Роль | Права |
|---|---|
| **user** | Доступ только к Telegram-боту: чат с AI, список документов, инфо по документу. Доступа к веб-части нет. |
| **moderator** | Всё, что у user, + может апрувать/отклонять новых пользователей (кнопки в ТГ). Доступа к веб-форме загрузки документов нет. |
| **admin** | Всё, что у moderator, + доступ к веб-форме загрузки документов (авторизация по номеру телефона + одноразовый код в ТГ). |
| **super admin** | Всё, что у admin, + страница управления пользователями: назначение роли admin, деактивация пользователей. Не может снять роль супер-админа с себя. |

Апрув новых пользователей (см. п. 4.3) могут выполнять moderator, admin и super admin — любой из них, кто первым нажмёт кнопку.

Первый супер-админ создаётся через artisan-команду/сидер (вручную, вне общего флоу апрува). Остальным пользователям роль admin/moderator назначает super admin через веб-страницу управления пользователями (п. 3.2).

## 3. Веб-часть

### 3.1 Авторизация для формы загрузки документов

Форма загрузки документов (существующий Filament `DocumentResource`) закрывается авторизацией:

1. Пользователь вводит номер телефона на странице входа.
2. Номер ищется в таблице пользователей.
   - Если номера нет или роль пользователя — `user`/`moderator` (нет прав на веб) → отказ в доступе (без уточнения причины — просто "нет доступа").
   - Если номер найден и роль `admin`/`super admin` → генерируется одноразовый 6-значный код, отправляется пользователю в Telegram-бот (сообщением).
3. Пользователь вводит код на веб-странице. При совпадении — создаётся веб-сессия на **8 часов** (конфигурируемо).
4. По истечении сессии — повторный вход по тому же сценарию.

Код одноразовый, с TTL (например, 5 минут) и ограничением попыток ввода.

### 3.2 Страница управления пользователями

Доступна только `super admin`. Список пользователей с телефоном, именем (из Telegram), текущей ролью, статусом (активен/деактивирован). Действия:
- Назначить роль `admin` или `moderator` (понизить обратно до `user`).
- Деактивировать / активировать пользователя. У деактивированного пользователя нет доступа к боту (бот отвечает сообщением о блокировке на любое действие) и к веб-части.
- Super admin не может деактивировать или понизить в роли самого себя.

## 4. Telegram-бот

### 4.1 Первый запуск / онбординг

1. Пользователь нажимает `/start` (или пишет что угодно, если ещё не зарегистрирован).
2. Бот приветствует и присылает заготовленный текст о себе/боте (черновик — см. п. 4.1.1; язык по умолчанию — **украинский**).
3. Бот просит поделиться номером телефона через стандартную кнопку Telegram **"Поделиться контактом"** (номер подтягивается из аккаунта пользователя, без ручного ввода).
4. После получения номера создаётся запись пользователя со статусом "на рассмотрении" (pending) и сохраняется `chat_id`.

#### 4.1.1 Черновик текста приветствия (UA)

> Привіт! 👋 Я бот-асистент [название]. Допоможу знайти відповіді на твої запитання по нашій базі знань: можу знайти потрібний документ, стисло розказати, про що він, або просто відповісти на питання в чаті.
>
> Щоб почати користуватись ботом, потрібно підтвердити номер телефону — натисни кнопку нижче. Після цього заявку розглянуть наші адміністратори, і я напишу тобі, як тільки доступ буде відкрито.

(Текст черновой, можно скорректировать перед реализацией.)

### 4.2 Отправка заявки на согласование

При создании заявки (новый pending-пользователь) всем пользователям с ролью `moderator`/`admin`/`super admin` в их личные сообщения с ботом отправляется карточка с информацией о заявителе (имя, номер телефона, username, дата обращения) и двумя кнопками: **Одобрить** / **Отклонить**.

### 4.3 Обработка решения

- Любой из получателей нажимает одну из кнопок.
- Заявителю отправляется сообщение о результате (одобрено → доступ к боту открыт, роль `user`; отклонено → доступ закрыт).
- Карточка во всех остальных личных сообщениях, где она была отправлена, редактируется — кнопки убираются, добавляется отметка, кто и как обработал заявку (например: "✅ Одобрено (Иван Иванов)").
- Повторное нажатие кем-то другим после обработки — игнорируется / сообщение "заявка уже обработана".

#### 4.3.1 SLA на рассмотрение

Напоминание по необработанной заявке отправляется **на следующее утро** (например, в 9:00 по умолчанию, значение времени — в конфиге), но только если с момента создания заявки прошло **не менее 12 часов**. Если заявка создана поздно вечером/ночью и к ближайшему утру 12 часов ещё не набралось — напоминание переносится на следующее утро после этого.

При срабатывании: всем moderator/admin/super admin повторно отправляется напоминание (новое сообщение с заявкой и кнопками), а предыдущее отправленное сообщение с заявкой у всех деактивируется (кнопки убираются, помечается как "⏰ напоминание отправлено повторно"). Цикл повторяется каждое следующее утро, пока заявка не будет обработана.

### 4.4 Доступ к боту

- Пользователи со статусом pending/отклонён/деактивирован — на любое сообщение получают ответ о том, что доступа нет (с соответствующей причиной), и не могут пользоваться функциями бота.
- Доступ есть только у approved и активных пользователей.

### 4.5 Команды и кнопки бота

Главное меню (reply/inline-кнопки):

- **Смена языка** — ru / en / ua (по умолчанию — ua). Выбор сохраняется в профиле пользователя и используется для всех последующих ответов бота (включая инфо по документам).
- **Хелп** — список всех доступных команд с описанием.
- **Список документов** — пронумерованный список названий документов с прямой постоянной гиперссылкой на скачивание каждого файла (без истечения срока действия).
- **Инфо по документу** — пользователь выбирает документ (например, по номеру из списка), бот присылает краткое резюме "о чём документ", сгенерированное AI. Резюме кешируется в БД **per документ + per язык**, чтобы не запрашивать AI повторно на каждый вызов. Если резюме для выбранного языка ещё нет — генерируется один раз и сохраняется.

### 4.6 Свободное общение (чат с AI)

Если входящее сообщение не распознано как команда — оно передаётся в существующий RAG/AI пайплайн как обычный вопрос. Диалоговая сессия (контекст) привязана к `chat_id` и живёт **1 час с момента последнего сообщения** (конфигурируемый параметр в `config/rag.php` или аналогичном конфиге), после чего контекст сбрасывается и начинается заново.

## 5. Технические детали (ориентировочно)

- Новые сущности: `User` (расширение — телефон, роль, статус, telegram chat_id, язык), `UserApprovalRequest`/лог заявок, `OneTimeCode` (код авторизации для веб).
- Роли/права — через `spatie/laravel-permission` (как согласовано в `docs/new_scope_auth_telegram.md`), с добавлением роли `moderator`.
- Telegram: webhook, обработка inline-кнопок (callback query) для апрува и редактирования уже отправленных сообщений у других модераторов/админов.
- Кеш резюме по документам: новая таблица (document_id, locale, summary) или колонка-json на документе.
- Конфиг: TTL одноразового кода, длительность веб-сессии (8ч), длительность бот-сессии диалога (1ч), список ролей, которые видят кнопки апрува.
